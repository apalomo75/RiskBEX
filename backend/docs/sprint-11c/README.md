# Sprint 11C — GitHub runner updates / Actualizaciones mediante GitHub

Status / Estado: implemented and validated offline; not deployed or activated /
implementado y validado offline; sin desplegar ni activar.

Sprint 11D supersedes the rollout and approval details below: see
[`../sprint-11d/README.md`](../sprint-11d/README.md). The default bundle now requires
its independent approval even with a checksum pin; legacy root secrets exported

## Verdict and architecture / Viabilidad y arquitectura

Technically feasible on an ephemeral Ubuntu 24.04 runner, Python **3.11.14**.
The presentation remains Python 3.13, six bilingual views and the simulator.
Reuse `update_main`, frozen inference, CVaR mapping, regression gates, VersionStore
and `cloud_snapshot`; no quantitative implementation changed. Live Yahoo delivery
from GitHub IPs and a fresh dependency installation remain unproven.

Viable técnicamente con runner efímero. Se mantienen los modelos, cálculos,
Docker, updater local y presentación existentes. Falta validar instalación y
acceso real a Yahoo desde GitHub; no se han realizado descargas.

Recommended initial arrangement: **Git-backed snapshots in the existing deployed
branch**, orchestrated by a workflow installed on **main**. Checkout
`release/streamlit-rc1` explicitly; restore, infer, verify, export, and push one
normal fast-forward commit containing `cloud/publication` and `cloud/approval.json`.
The workflow in `.github/workflows/daily-update.yml` is manual, read-only and
OFFLINE. The future production template is `daily-update.yml.disabled`, outside
`.github`; it cannot execute. Neither file has been pushed. The previously tracked
workflow contains a cron and calls the updater without its required inputs; local
replacement does not disable any existing remote schedule.

Recomendación: mantener las coordenadas de Streamlit y publicar en su rama actual.
El workflow debe existir en `main`; ponerlo solamente en la rama de despliegue no
habilita el cron. La sustitución local no modifica la programación remota existente.

Alternatives / Alternativas:

| Option / Opción | Tradeoff / Compromiso |
| --- | --- |
| Git in deployed branch / Git en rama desplegada | No new service or credentials; atomic commit, easy rollback. Repository grows. / Sin servicio adicional; commit atómico y rollback sencillo; crece el repositorio. |
| Immutable object store / Objetos inmutables | Bounds Git growth, but adds authenticated writer, trusted pointer/signature, availability, egress and refresh code. / Limita Git, añade permisos, puntero fiable, costes y código de refresco. |
| Actions artifacts/cache / Artefactos o caché | Expiration/eviction and access requirements make these unsuitable as authoritative state. / Caducidad y acceso impiden usarlos como estado autoritativo. |

Merging all release work into main or changing Cloud's branch is unnecessary and
would increase scope. No external storage is needed initially. A move to storage
would require its own authorized implementation and the same distribution rights.

## Scheduling and calendar / Horario y calendario

Inactive proposal: `37 19,21 * * *` UTC daily, including weekends. Madrid execution
is 20:37/22:37 in winter and 21:37/23:37 in summer, always after the existing 20:00
availability policy. `SessionCalendar.eligible` applies Europe/Madrid semantics;
cron is not treated as exchange close. Second slot retries a failed first slot;
next successful run fetches **all** missing sessions with overlap validation.
No data revisions, gaps, non-trading observations or future bars are accepted.
Already-current sessions return success before downloading or exporting, without
a commit. Calendar expiry or a publication newer than the eligible date is an error.

Dos oportunidades diarias, fuera del minuto cero. Los retrasos de Actions no cambian
la fecha de mercado; se calcula en ejecución. Una sesión vigente no descarga ni
publica. Los huecos pendientes se recuperan juntos si el proveedor los entrega.

GitHub schedules can be delayed/dropped, and public-repository schedules may be
disabled after inactivity. This is best-effort automation, not an SLA. Timeout:
20 minutes covers cold dependency installation and inference with ample margin;
there is no long-running daemon. Global workflow concurrency queues rather than
cancels active work; VersionStore flock protects the local process. An intervening
remote commit rejects the normal push. Do not force, rebase or retry a stale
candidate: restart from the latest branch.

No new calendar dates were guessed. Use BME's annual official market calendar,
review its holidays and exceptional sessions, record source/review date, and extend
configured coverage before the final 2026 publication that needs a 2027 target.
Preserve old holidays and original manifests. Review annual updates in November;
test year boundary, Easter, May Day and DST. Config-only changes do not require
altering model hashes or refitting. The current default calendar path is retained;
a reviewed extension can add years to that configuration in a separate authorized
change. No exchange-calendar library was installed.

El calendario debe revisarse antes del cambio de año, incluida la siguiente sesión
objetivo. La caducidad bloquea también la frescura presentada; no se inventan festivos
ni se modifica la procedencia de publicaciones históricas.

## Publication, Cloud and trust / Publicación, Cloud e integridad

`candidate` checks bootstrap/gate/calendar, calls the unchanged MAIN updater, and
exports a complete new bundle to a new temporary directory. `promote` is an explicit
future operation: clean release branch and expected HEAD required, complete seal,
advancing market date and predecessor version checked, only snapshot and approval
staged, single commit, normal push. There is no push trigger. The manual offline
workflow has `contents:read` and no stored checkout credentials. Future publishing
requires job-level `contents:write`, explicit distribution approval variable and
operator-approved branch policy; no PAT is required. GitHub's contents permission
is repository-scoped, not branch-scoped; this limitation must be accepted or a
separately constrained publishing identity introduced. Tokens are not printed.

El cambio remoto es atómico: cualquier fallo previo conserva la versión anterior.
Un fallo de push deja el remoto intacto; se descarta el checkout temporal. La
aprobación de distribución es obligatoria para la ruta CLI `--publish`.

`cloud/approval.json` binds exact snapshot checksum, version and market date outside
the payload. A reviewed Git checkout is the trust boundary, not a secret checksum
or self-declared inventory. The default Cloud entrypoint verifies that approval
and every payload hash plus the original allowlist. A stale **Streamlit Secrets**
checksum is superseded for the standard bundled path; no daily secret edits are
needed. Explicit environment checksum pins remain strict, including wrong-pin
failure; custom bundle paths need a valid external pin. Missing approval without
a valid pin, malformed approval or corruption stops the app. This protects integrity
under trusted Git writers; it is not an independent signature against a malicious
repository writer.

El checksum no se desactiva: pasa de secreto fijo a aprobación versionada con el
snapshot. La instalación inicial del nuevo entrypoint y aprobación requiere
autorización de despliegue. Un pin definido como variable de entorno debe retirarse
una sola vez o actualizarse explícitamente; no se ignora silenciosamente.

Streamlit monitors the configured release branch and copies committed changes.
Its dependency/runtime remains unchanged. On the next rerun, changed version clears
Streamlit data caches; existing navigation is preserved. Simulator results already
carry their own version and existing mismatch handling. Idle visitors may need a
rerun/reload; no continuous push to idle browsers is promised. Existing display
separates market session, pipeline generation timestamp and calendar freshness;
the Git publication instant is not fabricated from the market date. Scheduler
execution evidence is in Actions logs, not the public bundle: the UI must not infer
successful daily automation from a manifest or live-origin price provenance. The
app remains a daily end-of-session publication, not a live feed.

Cloud detecta cambios en su rama actual. La caché se invalida al cambiar la versión;
una sesión inactiva puede requerir recarga. No se afirma ejecución automática sin
logs. La frescura se calcula con calendario, no con la hora del commit.

## Failures, costs and recovery / Fallos, costes y recuperación

Failed provider, changed historical prices, gate mismatch, incomplete response,
inference failure or hash mismatch: no remote publication. See the failed Actions
step and rerun manually; do not edit receipts, prices or manifests to bypass checks.
Interrupted export stays in disposable storage. Interrupted local pointer promotion
is covered by VersionStore atomic pointer/orphan checks. Retrying from Git restores
the previous complete state. Rollback requires an explicitly reviewed **new commit**
restoring both the old snapshot and its matching approval; never force-push.
Stop future publishing before rollback and resolve the cause before resuming.

En caso de fallo se conserva el snapshot anterior. Recuperar mediante nuevo commit
revisado que restaure bundle y aprobación juntos; nunca forzar el historial.

Measured local regression: 7.01 s, 226,460 KiB peak RSS. Seven runner tests including
real two-session replay: 34.04 s wall, 243,192 KiB peak RSS. Actual replay outputs
match original prices/features/signals/backtests/metrics/turnover numerically.
These measurements exclude package installation and real network. Budget estimate:
1–5 minutes cold installation, under 2 minutes inference/export, 1 GiB RAM and 2 GiB
free working disk (plus runner toolchain); 20-minute ceiling. Network: GitHub checkout
and push, Python runtime download, PyPI/build dependencies and Yahoo only for live
updates. Yahoo rate limits, API changes, IP blocking and provider corrections remain
external failure modes.

Medidas locales, no SLA de GitHub. No se han medido descargas reales ni instalación
limpia. El runner estándar ofrece margen suficiente para estos consumos observados.

Standard public-repository hosted runner minutes are currently free. Artifact/cache
storage can have limits/costs; this workflow uploads neither market-data artifacts
nor daily caches. No VPS/object-store bill. Current snapshot: ~3.28 MB operational
store, ~4.55 MB research/figures, remainder metadata. New content-addressed directories
can add ~0.83 GB/year **unpacked** at 252 updates; total snapshot upper bound ~1.98
GB/year. Git pack/delta compression may reduce this, but indefinite Git growth is
not proved sustainable. Quarterly check GitHub repository size; propose migration
before 250 MB packed size or material clone slowdown. Keep shallow updater clones,
no retained daily CI artifacts; do not rewrite public history automatically. A future
storage design needs priced regional storage/egress and restricted write identity;
it is not silently substituted here.

Git es razonable para v0.1, con revisión trimestral y umbral de migración; no se
promete sostenibilidad indefinida. No se implementa infraestructura adicional.

Use GitHub failure notifications as the initial alert. A skipped job produces no
failure notification: daily check the published market session against the eligible
session and the latest Actions run. If unattended missed-run detection is required,
a separate independent freshness check needs later authorization. Green offline
validation proves no live update. Green unchanged is successful idempotency; green
published must also show new commit, matching approval and hosted app version.

## Distribution blocker / Bloqueo de redistribución

The current public bundle includes Yahoo-derived historical prices and derived
research. yfinance's Apache licence covers software, **not data redistribution**;
its own documentation says the Finance API is intended for personal use and directs
users to Yahoo terms. Yahoo legal pages returned HTTP 999 in this audit, so no claim
of a reviewed redistribution licence is made. Obtain a documented rights decision
covering source data, derived outputs and existing publication, or select a licensed
provider with an authorized migration. Owner approval alone does not create data
rights. Changing to object storage does not resolve this. No new data was published.

Se requiere una decisión documentada sobre derechos de datos y derivados. Cambiar
el alojamiento no elimina la restricción; no se han redistribuido nuevos datos.
